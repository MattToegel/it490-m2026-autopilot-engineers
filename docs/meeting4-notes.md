RabbitMQ Cross-VM Connectivity Documentation
Group Name: Autopilot Engineers
Assignment: MQ Practice Group Assignment
Tool Used
For the MQ Practice Group Assignment, our team used Tailscale to support cross-VM communication between team members’ virtual machines.
Tailscale allowed each group member’s VM to join the same private network, called a Tailnet. This allowed the VMs to communicate using private Tailscale IP addresses.
Why Tailscale Was Used
Tailscale was chosen because the assignment required multiple VMs to communicate with each other. Since each group member had their own VM, the client VMs needed a reliable way to connect to the RabbitMQ server VM.
Tailscale was useful because:
* Each VM had a private Tailscale IP address.
* All group VMs could communicate within the same Tailnet.
* RabbitMQ did not need to be exposed to the public internet.
* Client VMs could connect to the RabbitMQ server VM using its Tailscale IP address.
Server and Client VM Layout
Our group assigned one VM as the RabbitMQ server VM. This VM had RabbitMQ installed and running. The RabbitMQ server VM accepted messages from the client VMs and sent responses back through the message queue.
The rest of the team’s VMs acted as client VMs. These client VMs used the RabbitMQ PHP client sample code to send messages to the RabbitMQ server VM.
Why Client VMs Used the Server Tailscale IP
For cross-VM communication, client VMs could not use localhost or 127.0.0.1 as the RabbitMQ host. These addresses only point back to the same local machine.
If a client VM used localhost, it would try to connect to RabbitMQ on its own VM instead of the RabbitMQ server VM.
To avoid this, the client VMs used the RabbitMQ server VM’s Tailscale IP address as the broker host:
BROKER_HOST=100.122.175.95
RabbitMQ Client Configuration
The RabbitMQ client settings were stored in a file called testRabbitMQ.ini.
This file tells the RabbitMQ PHP client sample how to connect to the RabbitMQ server VM.
Example configuration:
BROKER_HOST=100.122.175.95
 BROKER_PORT=5672
 USER=test
 PASSWORD=test
 VHOST=/
 QUEUE=it490_sample_queue
 RESPONSE_TIMEOUT=10
The BROKER_HOST value points to the RabbitMQ server VM’s Tailscale IP address.
The BROKER_PORT value is 5672, which is the port used for RabbitMQ AMQP client connections.
The USER, PASSWORD, VHOST, and QUEUE values allow the client VM to authenticate with RabbitMQ and send messages to the correct queue.
Testing the Connection
After Tailscale and RabbitMQ were configured, the client VM tested the connection by running the RabbitMQ PHP client sample.
Command used:
php RabbitMQClientSample.php echo "ucid"
A successful test returned a response showing:
status => ok
 message => Echo: ucid
This confirmed that the client VM successfully connected to the RabbitMQ server VM through Tailscale and completed a send/receive RabbitMQ test.
Conclusion
Tailscale allowed our team to securely connect multiple VMs in the same private network. By using the RabbitMQ server VM’s Tailscale IP address, the client VMs were able to communicate with the server VM and successfully complete the cross-VM RabbitMQ messaging test.
